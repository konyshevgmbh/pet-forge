# pet-forge skill — Triggers + Invocation Flow

> Skill onboarding doc for AI coding agents. When a user says "I want to make a desktop pet," the agent should respond following this file's guidance.

---

## Triggers

Activate the pet-forge skill when the user's message contains these signals:

### Strong signals (must trigger)

- "I want to make (my own / a) desktop pet"
- "Make an SVG desktop pet / APNG desktop pet"
- "Help me make an idle animation"
- "How do I make a desktop pet"
- "Desktop pet [character name], [style]"

### Weak signals (ask before deciding)

- "I like some existing desktop pet example" (might want to fork rather than build new)
- "I want to make an animation" (might not be a desktop pet, could be some other animation)
- "Make a character" (might be a design request, not an animation one)

When a weak signal triggers, ask back: **"Are you looking to make a character with looping animation that plugs into a desktop pet runtime? Or just a single-frame animation/design piece?"**

### Anti-triggers (do not trigger)

- The user is already working on a specific product project, not trying to build a new character with pet-forge
- The user is just asking what an existing desktop pet is, not trying to build one

---

## First-Turn Response Template

Once the skill triggers, Claude's first message should not contain code — first **confirm 4 things**:

1. **What the character is**: "What character do you want to make? (e.g., orange cat / robot / mushroom / your own existing concept...)"
2. **Character topology**: "Is it head-only, head+body, or a single blob form? Does it have hands, feet, ears, a tail, antennae, props, eyes, a mouth? Is it grounded, floating, or edge-hugging?"
3. **Aesthetic direction**: "What style are you going for? (e.g., Apple-polished / pixel art / bouncy dopamine / zen minimalism / a reference image you provide)"
4. **Route preference**: "Do you want SVG or APNG? The two have very different characteristics: [show the route comparison table] — if you're not sure, start with SVG (free, hot-reloadable)"

---

## Route Selection Decision Tree

```
User answers "I want..."
   │
   ├─ "perfect loops / free / hot-reloadable" → recommend SVG route
   ├─ "fast results / cost doesn't matter / strongly stylized" → recommend APNG route
   ├─ "I can't code" → recommend APNG route (prompt engineering has a lower barrier than frontend animation)
   ├─ "polished, rounded vector look" → SVG route + apple-precise preset
   ├─ "pixel-art look" → SVG route + pixel-art preset
   └─ "want to try both" → start with SVG (lower barrier to entry), consider APNG once that's working
```

## SVG Route Workflow (skill-guided)

### Step 0: Character Topology Inventory

Don't assume up front that the character has a full head, body, hands/feet, and mouth. Ask:

- Main form: head only, head+body, a single blob, a prop/object, or some other silhouette;
- Face structure: does it have eyes, a mouth, blush, emoji-style symbols;
- Appendages: does it have hands, feet, ears, a tail, antennae, wings, props;
- Support relationship: grounded, floating, edge-hugging, mounted, or propped up by an object;
- Target motions: turning the head, tilting up/down, eye tracking, expressions, walking, waving, bouncing, floating.

Use the topology to decide which docs to read next:

- Needs face direction → `routes/svg/conventions/head-motion-axis.md`
- Needs main-body / body turning → `routes/svg/conventions/body-motion-axis.md`
- Has hands, feet, tail, antennae, props, or other appendages → `routes/svg/conventions/limb-rig-points.md`
- Has a mouth or multiple expressions → `routes/svg/conventions/expression-mouth-system.md`
- No hands, feet, tail, antennae, or props — don't force an appendage rig; fall back to main-body silhouette, center of gravity / floating baseline, and breathing only
- No mouth — don't force a mouth rig; convey emotion with eyes, eyebrows, blush, emoji-style symbols, or overall shape deformation

### Step 1: Establish the Character's Base Design

Ask the user:
- "Where's your character's base design coming from?" Three options:
  - A: Already have a PNG → use it directly
  - B: Want AI to generate it → recommend ChatGPT / Claude web / Midjourney generated by the user themselves (the skill does not call APIs)
  - C: Drawing it themselves → Figma / Procreate / etc.

**Key requirement**: make sure the user ends up with a **transparent-background PNG**. If it isn't transparent, guide them to process it with `rembg`:

```powershell
py -3.13 -m pip install "rembg[cpu,cli]"
py -3.13 -m rembg i input.png input-clean.png
```

Reminder: `rembg` is an external, optional tool that downloads a model on first run; don't treat it as a built-in pet-forge dependency.

### Step 2: PNG → SVG

Guide the user through running png2svg (`routes/svg/tools/png2svg/`):
- Flag the environment pitfall (must use py 3.13)
- Explain that the core vectorization engine is vtracer; pet-forge only handles transparent-pixel cleanup, background-removal fallback, quantization, scaling, and preset wrapping
- Use `--preset` to pick the right preset (apple-precise / pixel-art / high-detail)
- Recommended command: `py -3.13 png2svg.py input-clean.png character.svg --preset apple-precise`
- Check the output SVG's path count (< 50 is ideal, > 200 suggests simplifying)
- Explicitly flag: PNG→SVG only works well for simple, low-color, clean-edged graphics; photos, complex illustrations, fur, strong gradients, textures, and noisy images will cause path explosions or bad conversions — recommend switching to the APNG route or manually redrawing the key SVG structures
- Treat AI-generated reference images as storyboards / rough silhouette input, not as the delivery master straight out of vectorization; a delivery-grade SVG still needs organized layers, naming, anchors, and animatable paths

### Step 3: Apply a Preset + the hello-idle Template

Copy `routes/svg/templates/hello-idle.svg.html` to `<state>-v1.svg.html`:
- **Replace** the placeholder circle + eyes inside `<g id="pet">` with the character produced by PNG→SVG
- Adjust CSS variables to apply a preset (apple-precise / pixel-art)
- Double-click to open in a browser and check the result

If the character already has a layered master, copy parts from the master first — don't reverse-edit an old exported state back into the source file.
Before starting a multi-state character, read `routes/svg/conventions/layered-master.md` first to understand the distinction between the master, the library, and state export pages.

### Step 4: Polish the idle State

Follow the process in `routes/svg/conventions/iteration.md`:
- Start with v1 → watch it loop in the browser for 30s+ → review
- Archive dead ends to _archive, start v2
- Once it's good, lock it in — back up + write a spec
- Before deforming limbs, face edges, tails, hands/feet, etc., read `routes/svg/conventions/rig-first.md` first
- For states tuned via a tuner, once locked, bake them into canonical/showcase following `routes/svg/conventions/tuner-to-canonical.md`
- Before delivery, validate structure, scripts, embedding, looping, and target-environment behavior following `routes/svg/conventions/validation-runbook.md`

### Step 5: Expand States

Once idle is locked, **ask the user which state to do next**:
- Recommended order: idle → typing → thinking → sleeping → happy
- Repeat the polish process for each state
- Don't plan out 5 states all at once

### Step 6: Wire Up the Desktop Pet Runtime

Configure the theme/state mapping following `shared/state-map.md`, and integrate with the desktop pet runtime of your choice.

## APNG Route Workflow (skill-guided)

### Step 1: Establish the Character + Prepare the Main Reference Image

Guide the user:
- Write CHARACTER_PREFIX (reference the `routes/apng/prompts/template.js` template)
- Generate 1 main reference image (gen-images.js or the ChatGPT web app)
- Check: standard pose / neutral expression / pure green screen #00B140

### Step 2: Environment Setup

- `npm install` (Node dependencies)
- `pip install Pillow numpy` (Python dependencies; APNG assembly depends on ffmpeg)
- Install ffmpeg
- copy .env.example .env, fill in the API key

**Warn the user**:
- External generation APIs typically require an account, quota, or a paid plan
- Rate limits, queueing, and model capability on external APIs can change — reduce concurrency or retry later if needed
- Failed reruns are normal — budget 3 attempts per state

### Step 3: Generate the First Video

Guide the user:
- Edit the ANIMATIONS table in the prompt template, pick one state (recommend `idle-dozing`)
- Run `node gen-video.js idle-dozing --image <main reference image> --last-frame <main reference image> --api doubao`
- Review the output mp4, check for the 4 major failure types (deformation / camera movement / extra hands / background)

### Step 4: Chroma Key → APNG

`py chroma_key.py output/idle-dozing/doubao-video.mp4 output/idle-dozing/result.apng --plays 0`

Post-processing (as needed):
- Gray edges: `fix_gray_bleed.py`
- Dark-color bleed: `check_dark.py`
- File too large: `rebuild_apng.py --fps 12`

### Step 5: Expand + Wire Up the Runtime

Same as the second half of the SVG route. Configure theme.json following `shared/state-map.md`.

## 6 Things the Skill Should Remind the User Of (naturally, not all at once every time)

Bring these up as relevant (don't dump all of them at once):

1. **Don't lay out all 21 states up front**: polish 1 hero state first
2. **Back up before editing**: cp a copy as -backup-YYYY-MM-DD
3. **Archive dead ends, don't delete them**: keep them in _archive/ for traceability
4. **Watch it loop in the browser for 30s+**: a good-looking static frame ≠ a good-looking loop
5. **Character consistency is an engineering problem**: pin anchors down with library/ assets (SVG) / CHARACTER_PREFIX (APNG)
6. **Before external delivery, verify the real target first**: check the runtime / showcase / public asset before deciding something is a bug, an omission, or new scope

---

## What the Skill Should Not Do

- ❌ **Don't call generation APIs on the user's behalf**: the API key is theirs, the payment is theirs, and moderation/filtering compliance is theirs
- ❌ **Don't hand-write an entire character's SVG paths from scratch**: AI image generation / hand drawing / png2svg can produce a first draft, but delivery-grade SVG needs to come back to a layered master, readable paths, and stable anchors
- ❌ **Don't decide aesthetics for the user**: presets provide starting points, the user makes the final visual call
- ❌ **Don't promise "one-click generation of a complete multi-state character"**: polish 1 hero state first, then expand
- ❌ **Don't copy any existing product's character assets directly to the user**: unless the corresponding assets are explicitly licensed for reuse

## Feedback Loop

Once the skill is running smoothly, track where users' actual workflows diverge:

- If multiple users get stuck at the same step, the docs aren't clear enough → update the relevant routes/ / shared/ doc
- If a preset keeps getting overridden, its defaults are off → tune the preset's default parameters
- If users skip hello-idle and write states from scratch, the template isn't compelling enough → improve hello-idle's experience

The skill isn't done once it's written — it's a **product that iterates gradually**.
