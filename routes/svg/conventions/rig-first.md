# Rig-first deformation contract

> Read this page before working on any part that deforms — hands, feet, tail, antennae, face edges, clothing edges.

## Core rule

Don't drag the raw control points of a production path directly to make a deformation animation.

For parts that deform, first build or reuse a small rig:

1. Name the semantic anchors: root, contact point, bend point, tip, fixed edge.
2. Make the 0% path match the master literally first, before doing in-between frames.
3. Lock the end pose approved by the user/maintainer first, then tune easing and secondary motion.
4. In-between shapes are generated by the rig, not cobbled together from ad-hoc point edits.
5. Lock the tip in place unless the tip itself is the target of the motion.

A rigid transform is still a legitimate tool. When a part should genuinely translate, rotate, or uniformly scale as a whole, use `transform` directly. It's a mistake to use a whole-part transform, or hand-dragged control points, as a substitute for deformation.

## Neutral pose in motion

The `0` pose, the `middle` pose, and the endpoint in a motion must all come from the same geometric model.

Don't let the endpoint follow the anchor rig while the in-between frames switch back to the raw master path. If the two paths don't have identical point order, curvature, or boundaries, you'll get a snap when crossing the midpoint.

If you want to keep a static master, split it into two semantics:

- Static display: allowed to use the raw master path;
- Neutral pose during motion: keep using the same rig output.

## Axis-based deformation

Actions like turning the head, turning the body, lowering the head, weight-bearing — these usually aren't a whole-block translate or a whole-block rotate.

Define a semantic axis first, then distribute the deformation by weight:

- Low weight at the boundary, to avoid the whole block sliding;
- High weight along the axis/center region, carrying the directional change;
- Top/bottom or front/back can carry different weights;
- Smooth transition in the middle region;
- `0%` must equal the master or the confirmed starting point.

This rule applies to deformable structures such as the face, body, clothing edges, tail, and antennae.

## Preserving topology

If a closed contour is made of several cubic/quadratic segments, don't treat every number in the path as a contour point to be forced around.

A more stable approach:

- Find the main semantic anchors;
- Record the original handle ratios or tangent directions;
- Move the main anchors;
- Recompute the control handles in pairs;
- Reassemble into the same path topology and point order.

The pose can change, but the topology must not get scrambled. Otherwise in-between frames will show cusps, collapse, paper-thin flattening, or fail to interpolate.

## Dense warp requirements

Part paths often mix curves and straight lines. Sampling only `C` curves and ignoring `L` segments in a warp will break on mixed paths.

When doing a path warp:

- Parse the path data structurally;
- Support `M`, `L`, `C`, `Q`, and closepath as much as possible;
- Densely sample the centerline first, then map the contour;
- Preserve winding and fill behavior;
- Before trusting the animation, compare the generated 0% frame against the source path.

## Layers and contact relationships

Deformation often needs helper layers. Treat helpers as an explicit part of the rig:

- Name contact shadows, occlusion pieces, and local shading separately;
- Helper layers should be clipped to the body or parent surface that owns them;
- Don't hide an entire broken limb behind the body;
- If a helper has only been verified in a single pose, mark it pose-specific; re-check it visually before doing transition animation.

## Zeroing out transform-origin

SVG files often inherit CSS, e.g. `transform-origin: center`. If the rig's output writes an explicit `transform` attribute, reset it first for the animated part:

```css
transform-box: view-box;
transform-origin: 0 0;
```

Do this step before judging the geometry. A wrong origin will make a correct rig look like it's flying away.

## Acceptance checklist

Check before locking a rig animation:

- 0% equals the master pose;
- 100% equals the confirmed end pose;
- Loop or transition plays for at least 30 seconds with no drift;
- No sharp corners, collapse, or bulging at joints;
- Important identifying features are still visible;
- Checked at common browser zoom levels and in the target runtime/browser.

If the same issue fails the same way two rounds in a row, stop and don't keep patching symptoms. Record the current file, the symptom, what's been tried, and the boundaries, then re-review the rig choice.
